Supply-Chain Risk in the Age of Model Hubs

You didn't train it, you downloaded it. Pre-trained models, datasets and pip packages are a trust chain most teams never audit.

AI Security By RAJNISH KUMAR • 11 Jul 2026 • 7 min read

Pulling a model from a public hub feels like installing a library: one line of code, a progress bar, and you are in business. But a model artifact is not a static asset. Depending on the format, it can carry executable code, and even when it cannot, the weights themselves encode behaviour nobody on your team has audited. You downloaded it – you didn't train it – and that gap is the supply-chain problem.

The traditional software supply chain at least has decades of tooling behind it: lockfiles, signature verification, vulnerability feeds. The ML supply chain has almost none of that by default, while its artifacts are larger, more opaque, and pulled straight into production pipelines.

Pickle is an execution vector, not a file format

Most legacy PyTorch checkpoints are pickle archives. Pickle is a serialization protocol that can instruct the loader to import modules and call functions during deserialization – that is by design, not a flaw. A malicious checkpoint can therefore run arbitrary code the instant a load function touches it, before a single inference is performed. The same applies to the pickle-based artifacts scattered across data-science workflows: joblib dumps, cached preprocessors, serialized sklearn models.

The practical fix is safetensors: a format that stores raw tensor data plus a JSON header, with no code paths at all. Prefer it wherever the ecosystem supports it, refuse pickle-based artifacts from untrusted sources by policy, and when you genuinely must load one, do it in a sandboxed, network-isolated environment and scan it first – tooling exists that flags dangerous pickle opcodes before deserialization runs.

The threats that survive a safe format

Switching formats removes code execution, not malicious behaviour. Backdoored weights are the sharper problem: a model fine-tuned to behave normally on benign inputs but to misclassify, leak, or comply when a specific trigger appears. No scanner reads intent out of billions of parameters, so provenance becomes your only meaningful control.

Around the model itself sits the familiar package-ecosystem mess. Typosquatted namespaces on model hubs mirror typosquatted packages on language-package registries; an organisation name one character off the official one can serve a poisoned artifact to every pipeline that automates the pull. And upstream of the weights, dataset tampering quietly shapes what any downstream fine-tune learns – you inherit every corruption in the corpus, invisibly.

Provenance: pin, verify, sign

A model card is documentation, not evidence. Treat provenance the way you treat container images: pin downloads to an exact revision hash rather than a moving branch, verify checksums against a record you control, and prefer publishers who cryptographically sign their artifacts so a file is tied to an identity rather than a display name. Internally, sign the models your own teams promote, so a swapped artifact fails closed instead of loading silently.

An SBOM for the model, not just the code

Your application SBOM lists libraries; it says nothing about the component actually making decisions. Extend the inventory to ML-specific parts so that when a base model or public dataset is reported compromised, you can answer "are we exposed?" in minutes rather than weeks. At minimum, record:

  • The base model, exact revision, source hub, and checksum for every deployed model
  • Fine-tuning lineage: which datasets, which upstream checkpoints, which training code
  • The serving stack – inference server, tokenizer, and any conversion tools that handled the artifact
  • Who approved the model for production, and against which scan results

Scanning as a gate, not a suggestion

Put artifact scanning into the pipeline the same way you gate container images: block pickle-based formats by default, flag suspicious opcodes and embedded payloads, and quarantine anything that fails until a human looks. This will not catch a well-crafted weight-level backdoor – nothing off the shelf reliably does – but it raises the cost of the cheap attacks that account for most real-world abuse, and cheap attacks are the volume business.

The bottom line

Treat every model artifact as untrusted input from the internet, because that is exactly what it is. Standardise on safetensors, pin and verify every download, sign what you promote, keep an ML-aware SBOM, and gate ingestion with scanning. None of this requires exotic tooling – it requires deciding that models deserve the same supply-chain discipline you already apply to code.
