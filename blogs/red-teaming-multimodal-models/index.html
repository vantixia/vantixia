Red Teaming Multimodal Models: Images That Speak Injection

When a model can read images, an attacker can hide instructions inside a picture. Multimodal expands the injection surface dramatically.

Testing AI By RAJNISH KUMAR • 16 May 2026 • 7 min read

A model that reads only text has one door for untrusted input. Bolt on a vision or audio encoder and you have quietly opened several more. Every pixel and every waveform becomes a channel an attacker can write to, and those channels sail past most of the input filtering teams built for text. The malicious instruction never exists as a string until the model itself decodes it.

Red teaming these systems means treating the encoder as an untrusted parser and the content it produces as attacker-controlled input that lands in the same context window as your carefully written system prompt.

The encoder is a trust boundary you forgot to defend

When a caption model or a document-understanding pipeline turns an image into tokens the model can reason over, it is performing a translation your text guardrails never see. A regex that strips "ignore previous instructions" from a chat box does nothing when those words arrive as rendered glyphs inside a screenshot. The vision layer helpfully reads them back into the prompt for you.

The same logic applies to speech-to-text front ends, PDF and OCR stages, and any tool that converts a binary blob into text the model treats as trustworthy. If you have not drawn a boundary around that conversion step, you do not have a defence there.

Where the payload actually hides

Payloads exploit the gap between what a human reviewer notices and what the model faithfully ingests. A few patterns worth building tests around:

  • Text-in-image: instructions rendered as legible or near-illegible text, low-contrast overlays, or captions the OCR stage reads but a reviewer skims past.
  • Steganographic and metadata payloads: instructions tucked into EXIF fields, alt-text, or embedded document properties that a preprocessing step concatenates into the prompt.
  • Adversarial-visual perturbations: subtle pixel changes that steer a classifier's output or push a captioner toward attacker-chosen text.
  • Audio prompts: spoken commands, sped-up or layered speech, and clips crafted so the transcriber emits an instruction the human listener never registers.

The common thread is a mismatch between human perception and machine perception. Your test cases should deliberately live in that mismatch rather than testing obvious, plainly-readable injections.

Building a harness that exercises the whole pipeline

Testing the model in isolation misses the point. The interesting failures happen across stages: image lands, OCR extracts text, that text gets stitched into a prompt template, the model acts on it. Your harness needs to feed crafted media at the real entry point and inspect behaviour at the far end, not poke the model API directly with clean text.

Seed every payload with a distinctive marker so you can prove the instruction crossed the boundary. If the model produces the marker in its output, or takes the action the hidden instruction requested, you have a confirmed break. Track which stage decoded the payload – that tells you where the fix belongs.

Mitigations that survive contact

Isolation beats filtering. Decoded content from an image or audio file should be wrapped and labelled as untrusted data, never merged into the instruction portion of the prompt as if it were operator input. Give the model an explicit contract that content extracted from media is reference material, not commands.

Beyond that: constrain what actions a response can trigger when the input included media, keep OCR and transcription output out of privileged tool-calling paths without a human check, and log the extracted text so an incident can be reconstructed. None of these is a silver bullet, which is exactly why the red team keeps probing after each control ships.

The bottom line

Multimodal capability expands the attack surface faster than most teams expand their testing. Every encoder is a parser, every parser is a trust boundary, and the injection that matters is the one your reviewers cannot see but the model reads perfectly. Test the full pipeline, mark your payloads, and treat decoded media as hostile until proven otherwise.
