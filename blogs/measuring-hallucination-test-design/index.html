Measuring Hallucination: Test Design for Factual Integrity

A confident wrong answer can be worse than no answer. To manage hallucination you first have to measure it rigorously.

Testing AI By RAJNISH KUMAR • 12 May 2026 • 7 min read

"The model hallucinates" is a complaint, not a measurement. If you cannot attach a number to how often a system invents facts, under which conditions, and at what cost, you cannot tell whether a prompt change or a model swap made things better or worse. Test design is what turns a vague worry into a metric you can defend in a review.

This is a security concern more often than teams admit. A fabricated citation is embarrassing; a fabricated permission, a hallucinated API parameter, or an invented account balance can be the first link in an exploit chain.

Name the failure before you count it

Hallucination is not one thing, and lumping the varieties together produces a meaningless average. Separate them so each gets its own test coverage.

  • Fabrication: content with no basis in the input or in reality - invented names, numbers, or events.
  • Faithfulness failure: output that contradicts the source material the model was given, even when the source was correct.
  • Overconfident extrapolation: plausible-sounding claims that stretch beyond what the evidence supports.
  • Instruction-conflict invention: the model fills a gap it should have refused, answering when the honest response was "I don't know."

Each type has a different fix and a different risk profile. A faithfulness failure points at your grounding pipeline; a fabrication under refusal conditions points at calibration and abstention behaviour.

Building the test set

A factual-integrity suite needs questions with known, checkable answers and questions that have no answer at all. The unanswerable set matters most, because a healthy system abstains rather than confabulates. Mix in adversarial phrasing that invites the model to agree with a false premise, and edge cases where the correct answer is a partial one.

Pull questions from the actual domain the system serves. A generic trivia benchmark tells you little about a medical or financial assistant. Version the set, hold part of it back so improvements are not just overfitting, and record the provenance of every ground-truth answer so a reviewer can audit it.

Automating the score without fooling yourself

Reference-based scoring - comparing output against a known answer - is the sturdiest signal you have, and where you have references you should lean on them. Exact-match is too brittle for free text, so combine it with checks that tolerate wording while catching contradiction.

Using a model to judge another model's output scales well but carries real caveats. Judges inherit their own biases, can be swayed by fluent-but-wrong answers, and drift when the judge model updates. Calibrate the judge against a human-labelled slice, report its agreement rate, and never treat its verdict as ground truth for anything high-stakes. For grounded tasks, prefer a direct check that every claim traces back to a retrieved source over asking a model whether the answer "seems right."

When a wrong answer is a vulnerability

Draw the line at consequence. If a hallucinated output can trigger an action - a tool call, a transaction, a configuration change - then factual integrity is a security control, not a quality nicety. Test those paths as attack surface: can a crafted question coax the model into asserting a false capability, a non-existent user, or an unsafe default that downstream code trusts?

Setting thresholds and gating on them

A metric with no threshold is decoration. Decide, per hallucination type and per risk tier, what rate is acceptable, and gate releases on it. Abstention accuracy on the unanswerable set deserves its own gate - a model that answers everything confidently is failing even if its right-answer rate looks strong.

The takeaway

Factual integrity is measurable if you refuse to blur the categories, build a domain-specific set that includes the unanswerable, score with references where you have them and treat model judges with suspicion, and gate on numbers tied to real consequence. Do that and "it hallucinates" becomes a tracked, budgeted risk instead of a shrug.
